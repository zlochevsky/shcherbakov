# Перенос старых страниц в Hugo: правила и проверки

Справка для переноса страниц старого сайта и копирования чужих публикаций (например, шаг 2 плана
[praises-toc-plan.md](praises-toc-plan.md)). Собрано из плана переноса «Фан-клуба» (перенос завершён 2026-10-07;
ход работ по волнам — в истории git, файл `docs/fanclub-migration.md` до его удаления 2026-11-11). Решения о границе
витрины и клуба — [showcase-and-club.md](showcase-and-club.md).

## Правила переноса

- Шаблон `praises-article` + явный `backUrl` (после Волны 0 — по умолчанию по
  разделу). Ссылки только **относительные** (не `/…` от корня — сайт живёт под
  `/shcherbakov/`); `htmtexts/<y>/<id>.html` → `texts/<y>/<id>.html`; количество
  `../` считать от реального места нового файла.
- Сохранять **всё**: e-mail, HTML-комментарии, блоки, «не влияющие на содержание» —
  в том числе не вычищать их «из соображений приватности». Опечатки исходника сохранять.
- Хабы называть `<раздел>-index.md` с `url: …/index.html`.
- Строка с 4+ пробелами или табом перед блочным HTML-тегом в Markdown становится
  code block — проверять `grep -Pn '^(\t|    )' content/<раздел>/*.md`.
- Приведение регистра тегов — quote-aware (значения атрибутов не трогать),
  отдельным коммитом.
- Ассеты: у каждого `<img>`/файла должен быть реальный файл в `static/` (сначала
  искать в `static/Images/`, `static/fans/`, потом в исходниках `www/Images/`).
- Git: `public/` в `.gitignore`, в git из него ничего нет (последние давно закоммиченные
  файлы убраны 2026-10-02); добавлять только явные исходные пути.
- Клуб → витрина ссылаться можно; нельзя ставить в статьи новые ссылки «вперёд»
  на клубные страницы из витрины (проверяет `check-separation.py`).

## Своя разметка статей

- **Своя разметка.** Спойлеры ответов в `chgk`/`chgkizb` — `span.spoiler` (невидимы, пока не выделишь мышью, как на старом сайте);
  подсвеченные рифмы в `kogolublu` — `span.rhyme`; цветные даты (`discussion`, `eslinado`, `lirika`) — `span.datum`; стихи в
  `<br>` — `p.verse`, `<pre>` — шрифт страницы. Стили — `assets/css/praises-article.css`.

## Как проверять каждую партию

- `python3 scripts/check-links.py --section fans` — цели должны уходить из списка;
- `python3 scripts/check-separation.py` — новых нарушений быть не должно (клуб
  ссылается на витрину свободно, обратное — нет);
- сверка «источник ↔ md» по блокам, e-mail и HTML-комментариям; счёт слов
  **не ловит** потерянный последний блок — смотреть его отдельно;
- битые `#якоря` (файл есть, `name=`/`id=` нет; `#top` игнорировать) — скрипта
  в репозитории нет, писать разовый;
- проверки содержимого страницы (`<pre>`, сущности, `<blockquote>`) — только внутри `<main>`: в `<style>` шаблона статьи
  есть CSS-комментарии со словом `<pre>`, и поиск по всему HTML даёт ложные срабатывания (добавлено 2026-10-15);
- каждая картинка `<img src>` существует в сборке; картинка может лежать в общей папке старого сайта `/Images/`, а не
  в папке раздела — искать на зеркалах и в Wayback Machine; если её нет нигде, оставить как в исходнике и записать;
- исходник без разметки (голый текст писем без `<pre>`/`<p>`/`<br>`) браузер склеивал в один абзац — оборачивать в `<pre>`
  (`src_fn` в meta-модуле);
- ссылка на якорь `index.html#…`, когда якорь стоит на этой же странице, — ошибка исходника, исправлять на `#…`;
- `<blockquote>` вокруг всей страницы или её разделов — вёрстка старого сайта (текст выходит курсивом), снимать;
  настоящие цитаты и эпиграфы оставлять — смотреть глазами;
- заголовок новой страницы не должен совпадать с уже существующими; автор — по `From:` и по подписи в конце страницы,
  при нескольких отправителях — не ставить;
- проверки читают собранный сайт: `public/` или другой каталог сборки (`--public <каталог>`);
  если параллельно работает `hugo server`, собирать в отдельный каталог из копии проекта
  (сервер держит `.hugo_build.lock`).

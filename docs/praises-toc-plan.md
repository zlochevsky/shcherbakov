# План: самособирающееся оглавление «Отзывов и критики» (`praises.md`)

Записано 2026-10-21 по обсуждению с владельцем. Уточняет и заменяет для «Отзывов» шаг 4 из
[editor-pages-plan.md](editor-pages-plan.md) (часть шага 4 про «Фан-клуб» остаётся как записана там).

**Цель**: оглавление собирается само из полей статей, а читатель может упорядочить его по-разному — по рубрикам,
по авторам, по истории публикаций, по поступлению на сайт. Главное условие владельца — **работа редактора не должна
заметно вырасти**: одна форма на статью, обязательных полей немного, остальное — по необходимости.

## Исходное состояние

Разбор `content/praises.md` скриптом (2026-10-21, без правок файла):

- **130 статей** в семи рубриках (плюс 3 строки «Тексты, которыми мы не располагаем»); **14 групп** — родительский
  пункт списка с описанием автора («Дмитрий Быков, поэт, писатель и журналист. Статьи, заметки и стихи»), под ним
  статьи.
- **Автор** определяется сам у 116 из 133 записей (87 %): 69 — жирным в начале пункта, 47 — из родительского.
  Остальные 17 — в основном честно без автора («Википедия», анонс, анонимное эссе, энциклопедии); 4–5 — оформлены
  иначе (например, «Истомин С., Денисенко Д.» не жирным).
- **Дата появления на сайте** (`<span class="datum">`) — у 108 из 133 (81 %).
- **Год публикации** — у 70 из 130 (54 %): 26 надёжно (после `//` в библиографической части), 44 угаданы по тексту и
  требуют проверки (как минимум один неверен: «Пейзаж с Щербаковым» — год переиздания в книге, а не статьи). Без года
  63 — почти вся рубрика «Опубликовано на нашем сайте» и «Изыскания»; у 50 из них есть дата на сайте.
- **Ссылки**: 101 запись ведёт на свою страницу в `content/Praises`, 30 — на внешний сайт или другой раздел сайта
  (FOM, fans, Books), 2 — без ссылки. Поэтому оглавление только из front matter статей сейчас половину списка не
  покрыло бы.
- **Порядок сейчас** (вступление `praises.md`): в рубриках — по фамилиям авторов, работы одного автора — по времени.
- Поля статей сейчас: `title`, `params.author` (у 103 из 110), `params.subtitle`, `lastmod` (у 91; по нему — дата
  раздела в меню), `url`.

## Решения

1. **Сетевые публикации — на свои страницы.** Каждую доступную копируем на новую страницу сайта: стили и вёрстку
   приводим к сайту (по правилам перевода HTML в Markdown), вверху — ссылка на источник. Недоступные — ищем копии в Сети
   (в том числе web.archive.org). Деление «сетевые / опубликовано на нашем сайте» исчезает; рубрика означает **место
   первой публикации**: печать / Сеть / эфир / наш сайт / справочное издание / исследование.
2. **Две даты — две роли, не смешиваются:**
   - **год публикации** (`year`) — когда текст появился в мире; по нему порядок «по истории». У статьи, впервые
     вышедшей на сайте, он не вводится — берётся из даты на сайте. У давнего печатного издания без точной даты —
     приблизительный («~1990»): только для сортировки, на странице не выводится;
   - **дата на сайте** (`added`) — когда запись появилась у нас; по ней «новое» и порядок «по поступлению». У давних
     записей её может не быть — они просто не попадают в «новое». У копий сетевых публикаций — отдельная дата копии
     (`copied`), выводится «копия от …», «новым» запись не считается (иначе разом «новыми» стали бы ~30 старых статей).
3. **Порядки для читателя**: по рубрикам (по умолчанию — как сейчас: в рубрике по фамилиям, у автора — по времени),
   по авторам, по истории (`year`), по поступлению (`added`). Без JavaScript (поисковики, печать) — порядок по умолчанию.
4. **Замечания хранятся при том, что описывают** — тогда при любом порядке не теряют смысла:
   - об авторе — в справочнике авторов; выводится заголовком группы при порядке «по авторам» и при рубриках;
   - о тематической подборке («Бемоля и ямба гибриды») — в справочнике подборок;
   - о рубрике (вступление) — в справочнике рубрик; выводится при порядке «по рубрикам»;
   - о статье («отзыв амбивалентный», «прислал …») — в описании статьи (`blurb`);
   - отклики на статью — поле `responseTo` у отклика; отклик выводится под статьёй.

## Поля статьи (front matter, форма «Рецензия» в Sveltia)

| Поле | Что | Обязательно |
|---|---|---|
| `title` | название (есть) | да |
| `params.authors` | список авторов — выбор из справочника (связь `relation`, несколько значений) | да, кроме анонимных |
| `params.rubric` | место первой публикации — выбор из справочника рубрик | да |
| `params.year` | год публикации: `1997`, `1997-11`, `~1990`; пусто — если впервые на сайте | почти всегда |
| `params.source` | библиографическая строка («Знамя. 1997. № 11. С. 46»), в списке — после `//` | для печати |
| `params.sourceUrl` | оригинал; у копии — откуда скопировано | для копий |
| `params.added` | дата появления на сайте (нынешний `datum`) | нет |
| `params.copied` | дата копии сетевой публикации | для копий |
| `params.blurb` | описание в оглавлении, одна-две фразы, Markdown | нет |
| `params.responseTo` | адрес статьи, на которую это отклик | нет |
| `params.series` | тематическая подборка | нет |
| `params.mention` | упоминание (нынешнее «…и не только») | нет |

`lastmod` не трогаем — по нему дата раздела в меню (шаг 3 плана редактора); правка статьи не делает её «новой».
`params.author` (строка) заменяется на `params.authors` при переносе.

## Справочник `data/praises.json` (форма «Отзывы: справочник» в Sveltia, коллекция из одного файла)

- `authors` — `name` (как выводится), `sort` (фамилия для порядка), `about` (описание, Markdown), `link`.
  Список держать по алфавиту: в выпадающем списке формы статьи порядок — как в файле.
- `series` — `name`, `about`.
- `rubrics` — `id`, `name`, `about` (вступление), порядок рубрик — порядок в списке.
- `entries` — записи без своей страницы: «Тексты, которыми мы не располагаем», ссылки, которые не копируем
  («Википедия»). Те же поля, что у статьи; вместо страницы — внешняя ссылка или ничего.

**Проверено по Sveltia 0.250.0** (описание типов пакета; в самом редакторе ещё не проверено): `relation` с
`collection` + `file` и `value_field: authors.*.name` берёт значения из списка внутри файла; `multiple: true` —
несколько авторов; поиск по списку есть. Ограничения: `sort_by` для ссылки на файл не применяется; нового автора из
формы статьи не добавить — сначала в справочник; переименование в справочнике статьи не обновляет.

## Шаги

0. **Зафиксировать версию Sveltia** в `static/admin/index.html` (сейчас грузится с unpkg без версии — всегда самая
   свежая; обновления почти ежедневные).
1. **Проверка внешних ссылок**: скрипт проходит все внешние адреса `praises.md` — жива / переадресация / мертва;
   для мёртвых — поиск копий (web.archive.org и др.). Итог — таблица владельцу.
2. **Копирование сетевых публикаций** на свои страницы `content/Praises/…`: оформление — по правилам перевода HTML в
   Markdown; вверху — источник (`sourceUrl`) и дата копии. Для «…и не только» — только фрагмент о Щербакове со ссылкой
   на полный текст (как отрывок из «Одина» Быкова), флажок `mention`.
3. **Справочник**: `data/praises.json` и коллекция в `static/admin/config.yml`; перенести описания авторов (14 групп),
   подборок, вступления рубрик; свести варианты имён («Дм. Быков» = «Дмитрий Быков», «А. В. Спиглазова» =
   «Александра Спиглазова», «Аннинский Л.» = «Лев Аннинский»; однофамильцы — «О. Елисеев» и «Никита Елисеев» —
   проверить).
4. **Поля статей**: добавить поля в форму `praises`; перенести данные из `praises.md` во front matter статей (скрипт +
   ручная проверка): авторы, рубрика, год, источник, дата на сайте, описание, отклики, подборки. Проверить 44
   угаданных года; вписать недостающие (13 записей без года и без даты; у откликов — год статьи, на которую отклик).
5. **Шаблон оглавления** (`layouts/miscellaneous/praises.html`): список из статей раздела и `entries` справочника,
   по умолчанию — как сейчас. У каждого пункта — атрибуты для сортировки (`data-year`, `data-added`, `data-author`,
   `data-rubric`). Сверить с нынешним оглавлением: те же ссылки, те же описания, тот же порядок.
6. **Порядки на странице** (JavaScript): кнопки «по рубрикам / по авторам / по истории / по поступлению»;
   перегруппировка с заголовками групп из справочника; выбор запоминается (localStorage).
7. **«Новое»** — по `added`, если не старше N месяцев; N — в `data/settings.json` (общий с «Фан-клубом», шаг 4 плана
   редактора).
8. **Документация и подсказки**: README (EN + RU), `docs/frontmatter.md` / `.ru.md`, подсказки полей в форме; подпись
   поля текста «Текст (HTML)» → «Текст» (после перевода статей в Markdown).

## Открытые вопросы

- **Права на копии**: полный текст чужой статьи — перепечатка; в старых записях отмечено «публикуется с согласия
  автора». Где автор жив и достижим — хотя бы сообщить; где нет — фрагмент со ссылкой?
- **«…и не только»**: фрагмент + флажок «упоминание» (предложение) или иначе?
- **«Новое» по `added`**, а не по `lastmod`, как записано 2026-10-16 в шаге 4 плана редактора, — подтвердить.
- **Порядок по умолчанию** — по рубрикам (как сейчас) или по истории?
- **Анонимные записи** при порядке «по авторам» — отдельной группой в конце?

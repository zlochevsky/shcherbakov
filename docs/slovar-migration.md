# Инструкция: перенос «Словаря заморских слов» в БД

Инструкция для следующей сессии. Держите при себе, но не воспринимайте как
техзадание слово в слово — по многим пунктам (разметка цитат, пары
«смотри также», порядок импорта) решения принимались по ходу дела в диалоге
с пользователем, сверяйтесь с ним на развилках.

## Контекст

Источник — `kom.html`/`kom2.html` с `lambda.mkshch.com/fans/` (оригинальный
двухстраничный словарь примечаний и комментариев к песням М. Щербакова, ~281
песня, ~900+ отдельных датированных заметок). Цель — перенести это в Directus
(новые коллекции `comments`/`works_see_also`) и вывести на новой странице
`kom.html` в стиле каталога — с поиском по названию/году/тексту заметки,
кросс-теговой подсветкой совпадений и сворачиванием статей по умолчанию.
Концепция и UX уже проверены на интерактивном прототипе (Claude-артефакт на
10 тестовых песнях, публиковался в этой же сессии ранее) — при уточнении
поведения поиска/подсветки/сворачивания опираться на него.

**Рабочий файл — `workfiles/slovar-merged.html`** (5388 строк, склейка обеих
исходных страниц). Он **не в git** (`workfiles/` в `.gitignore`), но лежит на
диске проекта постоянно — не искать в `content/`, не путать со scratch-путями
предыдущих сессий (`/tmp/...` — те не переживают сессию, в этот файл их
содержимое уже перенесено).

### Шаг 5 — редакторский проход (не механический)

Не начинали. По всему `slovar-merged.html`:
1. Встроенные цитаты из **чужих** произведений внутри тела заметок (сейчас
   размечены непоследовательно — местами `<i>`, местами вообще без разметки)
   привести к единому `<em>` (или `<q>`/`<cite>`, если решите на месте, что
   так семантичнее). Не путать с полем `excerpt` (цитата из **самой** песни,
   через `<em>` уже стоит с прошлой сессии) — тут речь о цитатах ИЗ ДРУГИХ
   произведений, встречающихся в тексте пояснения.
2. `<b>` внутри тела заметки, где это смысловое выделение (не заголовок

3. Разметить пары «явная ссылка A→B» для будущего `works_see_also` — искать
   `<a href="#slug">` внутри тела заметок (это внутристраничные
   перекрёстные ссылки между статьями, уже все переведены на плоский `#slug`

## Важные грабли

- **`workfiles/` не в git**, но персистентен на диске — рабочий файл там, не
  в scratch. Каждый раз перед продолжением проверять, что
  `workfiles/slovar-merged.html` на месте и это последняя версия (сверять по
  количеству строк/наличию `class="entry-date"` и т.п. маркеров прогресса
  выше).
- **`sed` с `#` как разделителем ломается**, если в самом паттерне/замене
  встречается `#` (а его много — URL-фрагменты, `#FF0000` и т.п.). Использовать
  `|` как разделитель `sed -i 's|...|...|g'`.
- **`<font color>` не единообразен по смыслу** — прежде чем что-то ещё в этом
  роде конвертировать одним махом, проверить разброс значений цвета
  (`grep -oiE '<font color=...'`), не только самый частый.
- **Directus: создание коллекции/поля/связи через RW-токен работает**
  (`POST /collections`, `/fields/{collection}`, `/relations`), но это НЕ даёт
  автоматически прав на чтение никакой роли, включая `ReadOnly` (ту, что
  использует сборка Hugo). После создания новой коллекции — обязательно
  `POST /permissions` с `{"collection": "...", "action": "read", "fields": ["*"],
  "policy": "<id политики ReadOnly>"}`, иначе сборка сайта будет получать
  пустые данные, хотя в самой БД всё есть и по RW-токену видно. ID политики
  `ReadOnly` на момент этой сессии — `7a949c6a-bad5-40cb-ba23-12251eaa7a3b`
  (можно перепроверить через `GET /policies` и сверить `name`).
- **Архивные редакции песен не получают своей `works`-записи** — `work_id` в
  любой связанной таблице должен указывать на канонический id (без суффикса
  `0`/буквы), а не на архивный. Если нужно сослаться именно на конкретную
  архивную редакцию (не на произведение вообще) — см. решение с
  `cycles_entries.page_id`, тот же приём воспроизводим и для `comments`, если
  где-то в заметках будет такая необходимость.
- **Не гадать по префиксу id** — несколько раз совпадение по первым буквам
  вело не туда (`pesenka`≠`pesenkao`, `obrasche`≠`obraschx`). Сверять по
  точному совпадению name/incipit **и** года.
- **Не reproducировать текст самих песен** — вся эта работа (и вся, что
  впереди) про структурную/метаданные-работу и про содержимое Словаря
  (комментарии, а не сами песни). Тексты песен создаются только через уже
  существующие в проекте `assets/texts/*.txt` (пользователь кладёт сам) — не
  скачивать и не писать их за него.

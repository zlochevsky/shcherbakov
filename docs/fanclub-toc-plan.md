# План: самособирающееся оглавление «Фан-клуба»

Записано 2026-10-16 по обсуждению с владельцем (выбран вариант Б). Для «Отзывов» то же решение уточнено и заменено
отдельным планом — [praises-toc-plan.md](praises-toc-plan.md) (2026-10-21): справочник авторов и рубрик, две даты,
порядки для читателя.

Сделанное раньше по редактору (форма новой страницы, «Порядок меню», даты в меню, все страницы в `/admin/`) описано
в README, «Правка в браузере» и «Меню», поля — в `docs/frontmatter.md`.

## Проблема

Оглавления — ручной текст в теле (`content/fans/fans-index.md` и т. п.): ссылки, разнородные описания (со ссылками
внутри), даты групп вписаны руками («Эссе и стихи 21.02.21»). Шаблон не знает, какая статья в какой группе, —
посчитать дату группы и показать дату статьи нечем.

## Решение — списки собираются сами из полей статей

- в форме статьи (Sveltia, коллекция «Статьи фан-клуба»): «Группа» (выбор: эссе и стихи, переводы, представления,
  иное творчество… — список групп раздела), «Дата» (`lastmod`, уже есть), «Порядок» (`weight`), «Описание для
  оглавления» (`params.blurb`: свободный текст, Markdown/HTML, ссылки внутри можно — формат как сейчас), флажок
  «Показывать дату в оглавлении» (обещан владельцу 2026-10-18);
- в теле оглавления на месте списка — шорткод `{{< section-list "articles" >}}`: статьи группы по порядку — ссылка,
  описание, дата статьи, пометка «новое»; у заголовка группы — самая свежая дата группы. Всё, что не список
  (мемориальные страницы, предупреждение о спойлерах, ссылки, социология), — ручной текст тела, как сейчас;
- новая статья в одной форме — сама появляется в оглавлении с датой; даты групп и разделов всегда сходятся.

**Даты в меню и подменю «Фан-клуба»** — через `params.menuDateFrom` страницы, на которую ведёт пункт (уже сделано для
раздела целиком: `club`, см. README, «Меню»): «Фан-клуб» — самая свежая из всего раздела рекурсивно; «Картинки» —
из раздела картинок; «комментарии» — из СЗС; «главная» — из остального фан-клуба. Для подпунктов понадобится
источник «по папке».

## Пометка «новое» (решение владельца 2026-10-16)

- **статьи** — автоматически: новая, если «Дата» (`lastmod`) не старше N месяцев; ручного флажка нет. N
  настраивается в Sveltia — отдельный файл настроек сайта (например, `data/settings.json`, коллекция-файл с числовым
  полем «Новизна статей, месяцев»); не в `config/_default/params.json` — тот не в репозитории (токен);
- **песни** — другой принцип: «новая, пока не вышла в исполнении на диске», с исключениями, флажок вручную; остаётся
  в Directus (`works.is_new`): там таблица с колонкой, сортировкой и массовой правкой, а в Sveltia каждое изменение —
  открыть запись, сохранить, отдельный коммит и сборка.

## Перенос

Описания ~50 статей — из тела оглавлений в формы статей; описания разнородные — полуручная работа (перенос —
разработчик, проверка — владелец). Оглавления после переноса сверить с нынешними (те же ссылки, те же описания,
тот же порядок). Новые поля коллекции — затем прогнать `scripts/sveltia-normalize.py`.
